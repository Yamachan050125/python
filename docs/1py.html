第１講ー１　Pythonの仕組み メモリの取り方

Python勉強会

作者

Yamato Fujii

重要目標

Pythonの仕組みと他言語との違いを理解しよう。

What is Python?

Pythonは、ソフトウェアを動かすプログラムという指示書で使用する言語である。その特徴は以下の文に集約できる。

Pythonは,高水準で動的な,インタプリタ―型のオブジェクト指向プログラミング言語です。(James R. (2021))

なんだこの文章は。何を言っているかわからないと思うので解説しよう。

マシン語と高級言語

コンピュータは0か1でしか理解できない。このコンピュータのための0と1でしか書かれていない言語をマシン語という。

しかし、人間は0か1のみを使って言語を書くことは難しい。意味わからん。ということで、人間用にしたマシン語のことを高級言語（または高水準言語）という。

コンパイル言語とインタプリター言語

では、上記の文章を読み解くその１　「インタプリター言語」について解説していこう。

コンピュータは高級言語そのままは読み取れない。つまり、高級言語からマシン語への翻訳が必要である。この翻訳の仕方の違いが、コンパイル言語とインタプリタ―言語の違いである。

コンパイル言語は、コードを実行する際に、高級言語から一度マシン語へ一括翻訳（コンパイル）し、実行形式に直してから実行する仕組みである。Java, C#, C++などの言語は、このコンパイル言語にあたる。

一方、Pythonが採用するインタプリター言語は、翻訳は必要であるものの、これをライターが意識する必要がない。つまり、プログラムを呼び出すと逐次自動で翻訳と実行をしてくれる言語なのである。他にもJavaScriptなどもこの形式である。この言語は、実行の際にいちいちコンパイルする必要がないので、デバックが簡単。つまり、トライアンドエラーでの開発に有用なのである。

一つ文章をよみとけたね。次いきましょー！

オブジェクト指向言語

では、上記の文章を読み解くその２　「オブジェクト指向言語」について解説していこう。

オブジェクト指向とは

プログラムのなかで扱う対象をモノ（オブジェクト）に例え、オブジェクトの組み合わせによってアプリを形成していく手法のこと（山田（2025））

パワーポイントで言うならば、スライドを作る時に、テキストボックスとか、図形とか貼り付けてつくる。この一つ一つがオブジェクトという。

ほとんどの言語は、このオブジェクト指向言語なので、そう気にする必要はない。

ノート

厳密には、Pythonは純粋なオブジェクト指向言語ではない。様々な思想（パラダイム）を組み合わせているため、マルチパラダイムな言語とも言える。

1節のまとめ

よし。これで

Pythonは,高水準で動的な,インタプリタ―型のオブジェクト指向プログラミング言語です。(James R. (2021))

という文章の謎が解けたであろう。

つまり、高水準でとっても使いやすいトライアンドエラーのしやすい、モノを組み合わせた方式の言語ということだ。

しかも、Pythonは、初学者にも使いやすいように設計された言語なのである。

例えば、Hallo World! と打つとき

Javaの場合

public class Main {
    public static void main(String[] args) {
        System.out.println("Hallo World!");
    }
}

長すぎる。でも、Pythonの場合、

print("Hallo World!")
Hallo World!

これは使わない手はない。

Pythonにおける変数

基本文法を学ぶ前に、Pythonで重要な落とし穴があるので、そこを学ぶこととする。

Pythonの変数は箱ではなく名札

Pythonにおけるすべてのデータはオブジェクトである。ここが肝で、CやJavaだと変数＝データを保管する箱なのだが、Pythonにおいては、変数はオブジェクトなのでただの名札なのである。

例えば

a = 10  # 10というオブジェクトを作り、aという名札を貼る

メモリ上にまず「10というオブジェクト（実体）」が作られ、そこに「a」という名札を貼り付ける（参照する）。

変数名はそれに貼られたタグに過ぎない。つまり、名札を二つ以上つけられるのである。

a = 1000
b = a

print(id(a)) 
print(id(b)) 
2129768371568
2129768371568

↖数値が同じになっているはずだ。

問題点

これによって発生する問題が、中身を直接書き換えられるデータ型の場合に、他の変数まで連動して書き換わってしまう問題である。

数値や文字列は書き変わらないようになっている。つまり、数値や文字列への名札は一個しかつけられない状態にある。そのため、この場合は事故にはならない。

x = 10
y = x
x = 20  # xに20を代入（xの名札を別の「20」に貼り替えただけ）

print(y)  # 10のまま（yは元の10を指し続けている）
10

正確には、

int　float　str　tuple　frozenset

以上は、変わるように見えて実際には新しいオブジェクトを生成しているだけ。

しかし、リストや辞書は書き変わる。

list1 = [1, 2, 3]
list2 = list1  # 同じリストに名札を2つ貼った状態

list1.append(4)  # list1経由で中身を変更

print(list2)  # [1, 2, 3, 4] になってしまう！
[1, 2, 3, 4]

視覚化すると、名札を二つ付けるので、

そのあとに、list1.append(4) してしまうと、

list1だけを変更したのにもかかわらず、list2も変わる。 list2 は何も触っていないのに増えてしまうのである。

list　dict　set

この３つは中身を書き換える操作を行うと 同じオブジェクトが変更される事故の元である。

ノート補足　メモリの話

プログラムを動かすとき、Pythonは「作業机（メモリ）の上にデータを置くスペース」を確保する。

データを作る　例: 10 という数値を机の上（メモリ）に置く。

住所（アドレス）がつく　机の上にはマス目（番地）があり、「机の右から3番目、上から5番目」のように場所が決まる。

変数名（名札）を貼る 　人間が「番地：0x7ffee4…」と覚えるのは無理なので、そこにaという分かりやすい名札を貼る。

Pythonの場合は、変数分のメモリの場所を自動的に確保・不要となったら開放する。
